## 四、日常开发命令（本地，在项目目录执行）

```
npm install        # 首次装依赖
npm run dev        # 本地跑起来 http://localhost:3100
npm run db:push    # 数据库表结构同步（改 schema 后执行）
npm run typecheck  # TypeScript 检查
npm run test       # 单元测试（48 个）
npm run build      # 生产构建（注意：先停 dev server）
node e2e/verify-e2e.cjs        # e2e 回归（需 dev + 本地数据库在跑）
node e2e/verify-features.cjs   # e2e 功能 A-K
npm run qa:visual  # 视觉/对比度检查
```

本地开发时注册验证码会打印在 dev 终端日志里（`[DEV] 验证码 xxxxxx → 邮箱`），无需配邮件服务。

## 五、环境变量清单

| 变量 | 在哪 | 说明 |
|---|---|---|
| DATABASE_URL | .env.local（本地）/ Vercel | 本地连 localhost；Vercel 用 Supabase **Transaction pooler（6543 端口）** |
| AUTH_SECRET | 同上 | 会话+拼图签名密钥（openssl rand -base64 32 生成） |
| RESEND_API_KEY | Vercel（本地可选） | 验证码邮件发送 |
| MAIL_FROM | Vercel（本地可选） | 发件人，如 面试与笔试日程 <noreply@你的域名> |
| GOOGLE_CLIENT_ID / SECRET | Vercel | Google 日历同步（2B 阶段用） |

## 六、数据库

- 本地：PostgreSQL（brew services start postgresql@17），库名 interview_scheduler
- 云端：Supabase；改表结构命令：
  ```
  DATABASE_URL='postgresql://postgres.<ref>:密码@aws-0-ap-southeast-2.pooler.supabase.com:5432/postgres?sslmode=require' npx drizzle-kit push
  ```
- 表：users（含 seeded_at、calendar_feed_token）/ sub_calendars / interviews / email_verifications

## 七、部署流程（全自动）

`git push origin main` → GitHub → Vercel 自动构建部署（约 1 分钟）→ 线上生效。
改环境变量后需要去 Vercel Deployments 页点一次 Redeploy 才会生效。

## 九、安全基线（已实现）

- 密码 bcrypt 哈希；会话 httpOnly 加密 cookie
- 注册：拼图滑块 + 邮箱 6 位验证码（10 分钟/5 次试错/一次性）
- 频率限制：邮箱 5 次/时、IP 20 次/时、60 秒间隔
- 数据隔离：所有查询带 user_id，越权 404（e2e 实测）
- 验证码只存哈希；IP 只存哈希；订阅链接 token 可随时重置
